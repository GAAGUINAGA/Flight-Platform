# ADR-F12b-02 — Contrato HTTP interno Gateway→ESB
- Estado: Aceptado · Fecha: 2026-10-31 · Fase/Tarea: F12b-1 / Bloque 0
## Contexto
El gateway debe conservar su traducción de errores a HTTP sin cambios.
## Decisión
`POST /internal/v1/operations/{dominio.operación}` con `X-Internal-Key`, `X-Correlation-Id`, `X-Owner-Id`/`X-Role`, `Idempotency-Key` (informativa) y `X-Deadline-Ms`. Cuerpo `{input}` (el mensaje gRPC). Respuesta `{ok:true,result}` o `{ok:false,error:{source,grpcCode,grpcStatus,catalogCode,step?}}`. El gateway reconstruye errores con `code` numérico y `details` = código del catálogo. Tablas de errores en `docs/dev/f12b1-diseno-esb.md` §4.
**Verificación de rol (D-4, corregida por el humano: defensa en profundidad).** El ESB confía en la identidad (`X-Owner-Id`, `X-Role`) solo si llega con llave interna válida; sin llave ⇒ 401 antes de la mediación. Además, en las operaciones administrativas y de sistema el catálogo declara `roles` y el ESB rechaza antes de llamar al servicio si `X-Role` no está entre ellos: `{ok:false,error:{source:'service',grpcCode:7,grpcStatus:'PERMISSION_DENIED',catalogCode:'PERMISSION_DENIED'}}` (HTTP 403). Es el mismo error que daría el microservicio, así que el gateway lo traduce igual (`source:'service'` a propósito: con `esb` el gateway lo mapearía a INTERNAL). Los roles reproducen **exactamente** lo que hoy exige cada microservicio (`requireRole`), verificado en su código: `admin` en `guardar-instancia`, `cerrar-instancia`, `guardar-tarifa`, `listar-tarifas`, `registrar-novedad-operativa`, `contar-check-ins`; `system` en `reservas.listar-por-vuelo`, `sistema.expirar-holds`, `sistema.reanudar-pendientes`, `sistema.despachar-webhooks`, `sistema.recuperar-check-ins`. Las operaciones cuyo control de rol vive solo en el gateway (consultas de inventario, `clientes.publicar-evento`) quedan con `roleHint` informativo: el ESB nunca endurece más de lo que hoy acepta el servicio. El microservicio sigue siendo la autoridad. Pruebas: `ESB-ROLE-01..06`.
## Consecuencias
`asProblem`, `problemFromGrpc` y `v2ProblemFromError` no cambian. ESB caído o plazo vencido ⇒ 503 + `Retry-After`. El ESB valida el sobre con Zod, no el contenido de `input` (lo valida el servicio dueño). Errores propios del ESB (401/404/400/500) llegan al gateway como `INTERNAL` (500 genérico), nunca como 401 al cliente.
