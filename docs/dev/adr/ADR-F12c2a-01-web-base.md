# ADR-F12c2a-01 — Base de la web: cliente GraphQL propio, codegen propio, paquetes consumidos desde su fuente y versiones para Node 20
- Estado: Aceptado · Fecha: 2026-11-13 · Fase/Tarea: F12c-2a
- Concreta `ADR-F12c-01` (decisión 10) y `ADR-F12c-04` («Pendiente para F12c-2: tipos generados y el cliente GraphQL de la web»). Diseño: `docs/dev/f12c0-diseno-front.md` §2, §6.3, §6.5, §8, §9, §10.2.

## Contexto
El encargo pide la web con «el cliente GraphQL elegido en ADR-F12c-04», pero ese ADR dejó la elección para esta fase. Además había que decidir cómo generar tipos, cómo consume la web los paquetes compartidos, cómo llega la tabla única de zonas al navegador y qué versiones usar con Node 20 (fijado en `.nvmrc` y `engines`).

## Decisión
1. **Cliente GraphQL propio sobre `fetch`** (`platform/web/src/data/graphql-client.ts`, ~130 líneas, sin dependencias): las operaciones son las publicadas (texto canónico), no hay caché normalizada ni suscripciones que justificar, y funciona igual en React Native. Es la **única** puerta al backend (una prueba falla si aparece otro `fetch`). Hace lo que pide el diseño: `X-Device-Fingerprint` (UUID aleatorio guardado, sin datos del navegador), `X-Correlation-Id` por intención, `Authorization` si hay sesión, errores por `category`/`code` con catálogo propio en español, reintento solo de lecturas ante `UNAVAILABLE` (máx. 3, retroceso exponencial) y tiempo máximo total de 25 s. Descartados Apollo Client y urql: su valor (caché, enlaces) no se usa aquí y agregan superficie de auditoría.
2. **Codegen propio** (`packages/graphql-schema/scripts/codegen.cjs`, solo usa `graphql`): genera `generated/types.ts` (enumeraciones, entradas, fragmentos y tipos por operación) y `generated/operations.ts` (un documento tipado por operación con el texto canónico que acepta el servicio en producción). Los archivos se versionan y una prueba falla si hay cambios pendientes. Descartado GraphQL Code Generator: sus versiones actuales exigen Node ≥ 22 y las compatibles traen un árbol grande de dependencias de desarrollo.
3. **Paquetes compartidos** `design-tokens`, `brand`, `session`, `format`: TypeScript sin DOM ni tipos de Node (`lib: ES2022`, `types: []`; una prueba lo comprueba). La web los consume **desde su código fuente** (alias de Vite y `paths` de TypeScript), así el sitio se construye con `npm ci && npm run build -w @flight-platform/web` sin construir nada antes. Cada paquete compila además a `dist/` con `tsc`.
4. **Tabla única de zonas**: `AIRPORT_ZONES` y `zoneOf` pasan a `packages/shared/src/airport-zones.ts` (sin importaciones); `airport-time.ts` los reexporta (sin cambio para los servicios). `format` la importa por esa subruta y le suma los nombres para mostrar (hueco H-1). No se duplicó la tabla.
5. **Sesión** con `@supabase/auth-js` 2.109.0 (el cliente de Auth de `supabase-js`, sin Realtime/Storage/PostgREST que la web no usa; última versión que admite Node 20). PKCE, almacenamiento inyectado, `detectSessionInUrl: false` (la app canjea el `code` del enlace de forma explícita). El rol sale solo del claim firmado `app_role`.
6. **Herramientas y versiones exactas** (Node 20): React 19.3.1, React Router 7.18.5, lucide-react 1.72.0, Vite 8.3.8, Vitest 4.1.12, jsdom 29.1.1, Testing Library (react 16.3.3, dom 10.4.2, user-event 14.6.10), axe-core 4.14.0, Playwright 1.65.0. Sin `@vitejs/plugin-react` (Vite 8 compila JSX; se pierde solo la recarga en caliente), sin `@testing-library/jest-dom` ni `@axe-core/playwright` (exigen Node 22; se usan aserciones propias y `axe-core` directamente). Playwright usa el navegador instalado (Edge/Chrome): no descarga navegadores.
7. **CSP en dos capas con una sola definición** (`platform/web/security-headers.ts`): cabeceras de Render en `render.yaml` (incluye `frame-ancestors 'none'`) y `<meta>` generada al construir con las URLs reales de las variables. Una prueba y `check-deploy-env` comparan `render.yaml` con esa definición. La construcción falla si faltan las variables públicas obligatorias.
8. **Marca**: fotografías de Wikimedia Commons con licencia libre verificada (CC BY / CC BY-SA), crédito en `brand.config.ts`, en `CREDITS.md` y visible en el pie; Inter variable (subconjunto latino, OFL) autoalojada; logotipo e icono SVG propios. Ningún recurso de la plantilla.

## Consecuencias
- `packages/shared` cambia (reexportación) y `package-lock.json` también: al fusionar se disparan una vez los workflows que observan esas rutas.
- Nuevo workflow `web-ci.yml` (solo verificación; el despliegue es manual en Render). El e2e se ejecuta en local y en la auditoría.
- Sin caché de consultas: cada pantalla consulta al entrar. Si la parte b lo necesita (mis reservas, detalle), se evalúa entonces.
- `render.yaml` lleva la URL del servicio GraphQL **deducida** del patrón de Cloud Run del proyecto: el humano debe verificarla antes de publicar (guía §2).
- Fuera de esta entrega: compra, reservas, postventa, check-in y panel (F12c-2b y F12c-3); la pantalla «elegir oferta» es provisional.
