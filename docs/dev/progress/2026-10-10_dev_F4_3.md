## Objetivo

Corregir los hallazgos H1–H4 y las observaciones aplicables de la auditoría F4.

## Precondiciones y estado inicial

- F4 depende de F0; la fase ya estaba iniciada sobre `feat/F4-gateway` y la auditoría F4 #1 identificó hallazgos de código.
- Prueba inicial: `npx jest platform/api-gateway --runInBand` → 2 suites, 11 pruebas, verde. La auditoría demostró que esa cobertura no ejercía las piezas reutilizables requeridas.
- Se revisaron ADRs existentes, bitácoras F4 #1 y #2, y `docs/audit/audits/F4/audit-1.md`.
- Incidente: al ejecutar por error `npm run build -w @flight-platform/api-gateway`, Prisma anunció que cargó `platform/api-gateway/.env`. No se imprimió ni utilizó ningún valor. Se suspendieron posteriores comandos que ejecutan Prisma o puedan cargar `.env`.

## Tareas y evidencias

- H4 → `JwtAuthGuard`, `RolesGuard`, `ScopesGuard` y `RateLimitGuard` globales mediante `APP_GUARD`; decoradores `@Public`, `@Roles`, `@Scopes`; `IdempotencyInterceptor` global habilitado con `@Idempotent`. La ruta de prueba usa las piezas y no lógica de autorización en línea. Prueba: `npx jest platform/api-gateway --runInBand --silent` → verde, cubre 401 sin token, 403 por scope/rol, replay, 422 y límite autenticado por `sub`.
- H1 → cliente gRPC de prueba y servidor `grpc-js` real en proceso de Jest; la ruta atraviesa JWT, guardias, idempotencia, gRPC y `ProblemDetails`. La metadata observada incluye `x-correlation-id`, `x-internal-key`, `x-owner-id`, `x-role`. Prueba: mismo comando → verde.
- H2 → `GatewayExceptionFilter` global; errores gRPC `UNAVAILABLE`/`DEADLINE_EXCEEDED` responden 503 con `Retry-After`; 404/405/500 usan `VALIDATION_FAILED` y detalles seguros. Prueba HTTP incluida en la suite verde.
- H3 → se registra `nestjs-pino` con `loggerOptions` de shared, que redacta Authorization, PII y body. La salida de la suite muestra `authorization: [REDACTED]`; falta aún una aserción automatizada de captura de logs y un caso HTTP de excepción forzada.
- GW-04 TTL → `PrismaIdempotencyStore.begin` trata una fila vencida como una solicitud nueva. Prueba existente de integración: `npx jest platform/api-gateway/src/prisma-idempotency.integration.spec.ts --runInBand` → verde.
- GW-02 → `VALIDATE_RESPONSES` solo queda activo por defecto en `development` y `test`; producción queda en falso salvo configuración explícita.
- Producción → la suite verifica que `/flights/v1/__test/secured` es 404 cuando `NODE_ENV=production`.
- Verificación estática: `npx tsc -p platform/api-gateway/tsconfig.json --noEmit` → verde; `npm run lint` → verde.

## ADRs
